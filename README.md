# 사주정원 — 개인용 사주·만세력 1차 버전

React + TypeScript + Vite 기반 한국어 웹 앱입니다. 이름, 성별, 양력/한국 음력(윤달 포함), 날짜, 시간, 한국 출생지역을 입력하면 년주 | 월주 | 일주 | 시주와 천간·지지·오행·음양·십성·지장간을 표시합니다. 입력은 브라우저 안에서 처리하며 서버 전송, 계정, 자동 저장, AI 호출은 없습니다. 결과 JSON을 내려받을 수 있습니다.

## 실행

Node.js 22.12 이상(환경 검증: 24.19.0), npm이 필요합니다.

```sh
cd /workspace/saju-program
npm ci --cache /tmp/saju-npm-cache
npm test
npm run build
npm run dev -- --port 5173
```

다른 컴퓨터에서는 저장소 디렉터리에서 실행하세요. `npm run dev`는 개발 서버를 실행합니다. `npm run build` 결과는 `dist/`이며 정적 호스팅이 가능합니다.

## 계산 계약과 지원 범위

- 양력으로 변환한 날짜가 **1950-01-01~2030-12-31**, 출생지가 한국인 경우만 지원합니다. 한국의 과거 UTC+8:30 표준시와 서머타임 이력은 IANA tzdb 2026b에 따라 처리합니다. 해외 출생은 아직 지원하지 않습니다. 잘못된 날짜, 없는 윤달, 지원 범위 밖 날짜, 미상 시간은 오류로 거부하며 임의의 원국으로 대체하지 않습니다.
- **한국 음력 변환**: `korean-lunar-calendar@0.4.0`의 한국 달력 테이블. 중국 음력으로 대신 변환하지 않습니다. 프로젝트: https://github.com/usingsky/korean_lunar_calendar_js
- **간지·절기 엔진**: `lunar-javascript@1.7.7`. 프로젝트: https://github.com/6tail/lunar-javascript
- 년주는 설날이 아닌 **입춘 절입 시각**, 월주는 음력 월초가 아닌 **12절 절입 시각**으로 전환합니다. 출생기록의 당시 시계 시각에서 역사적 UTC 오프셋으로 실제 순간을 구하고, 절기 비교에는 이를 라이브러리의 UTC+8 시각으로 변환합니다. 일주·시주는 서머타임만 제거한 당시 표준시를 사용합니다. 두 시계가 섞이지 않게 별도로 계산합니다.
- 일주는 **23:00 자시 시작에 다음 일자**로 바뀌는 규칙(`sect=1`)을 채택합니다. 야자시/조자시 등 다른 학파 규칙은 지원하지 않습니다.
- 출생지역은 기록용입니다. **진태양시, 경도 보정, 균시차 보정은 적용하지 않습니다.** 지역을 선택해도 표준시 원국은 같습니다.
- 십성은 일간을 기준으로 오행의 생극과 음양을 비교합니다. 일간 자체는 `일원`으로 표시합니다. 지지 십성은 본기 지장간 기준이며, 모든 지장간의 십성도 따로 표시합니다.
- 지장간은 본기부터 표시하는 통상적인 배속표입니다. 자=계, 축=기·계·신, 인=갑·병·무, 묘=을, 진=무·을·계, 사=병·무·경, 오=정·기, 미=기·정·을, 신=경·임·무, 유=신, 술=무·신·정, 해=임·갑. 지장간 비율·사령·기간별 가중치는 계산하지 않습니다.
- 지지 음양은 자부터 양/음 교대하는 배속입니다. 오행 분포는 **천간·지지 8글자 단순 개수**이며 지장간 가중치, 신강/신약, 용신 판단을 의미하지 않습니다.
- 이름·성별은 원국 계산에 영향을 주지 않습니다. 향후 대운 방향 등 별도 기능에서 사용 가능합니다.

 tests/calculate.test.ts  계산·경계·데이터 계약 테스트

계산 엔진은 UI와 AI 코드에 의존하지 않는 순수 함수입니다. 미래 AI 제공자는 `SajuResult`를 입력받아 해석만 반환하도록 계약을 분리했습니다. 현재 AI 구현·키·호출은 없습니다. 대운·세운·월운·일진, 오늘/올해/내년 운세, 재물/직업/배우자/이동수, 궁합, 합·충·형·파·해, 신강/신약, 용신/희신은 아직 구현하지 않았습니다. 향후 `src/engine/fortune/`, `relations/`, `strength/` 등을 별도 계산 모듈로 추가하고 버전별 JSON 계약 및 검증 fixtures를 작성한 후 해석 모듈에 연결할 수 있습니다.

## 브라우저 검증

```sh
# 이 클라우드 환경에는 /usr/bin/chromium이 이미 있습니다.
SAJU_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

일반 로컬 환경에서 Playwright 브라우저가 없다면 신뢰할 수 있는 기본 다운로드를 사용하세요.

```sh
npx playwright install chromium
npm run test:e2e
```

브라우저 테스트는 개발 서버를 자동으로 시작하고, PC/390px 모바일에서 입력→원국 표시→JSON 다운로드, 범위 오류, 음력 윤달 변환, 페이지 넘침 및 런타임 오류를 검사합니다. 스냅샷이나 외부 AI 응답에 의존하지 않습니다.

## 1950~2030년 지원과 출생시간 보정

출생시간은 출생기록에 적힌 **당시 시계 시각**으로 입력합니다. 역사적 표준시와 서머타임 자료는 IANA tzdb 2026b의 `asia` 파일(ROK 규칙, Asia/Seoul 구역) 기준입니다: https://data.iana.org/time-zones/releases/tzdata2026b.tar.gz . 이력은 앱에 포함되어 브라우저·서버의 시간대나 ICU 버전과 무관하게 계산됩니다.

- 1954-03-21 전환부터 1961-08-10 전환까지 표준시 UTC+8:30을 적용합니다. 그 외 지원 기간의 표준시는 UTC+9입니다.
- 1950~1951년, 1955~1960년, 1987~1988년의 해당 기간에는 서머타임을 제거합니다.
- 예: 1988-07-12 당시 시계 01:30 → 표준시 00:30 → 자시. 1988년 겨울 01:30은 보정 없이 축시입니다.
- 전환 순간에는 시각이 건너뛰거나 중복될 수 있습니다. 예: 1988-05-08 02:30은 존재하지 않고, 1988-10-09 02:30은 두 번 존재합니다. 원국을 추측하지 않고 오류를 표시합니다.
- JSON과 계산 기준 화면에 실제 UTC 오프셋(분), 제거한 서머타임(분), 보정된 표준시, 시간대 자료 버전을 기록합니다. 진태양시 보정은 여전히 적용하지 않습니다.
- 지원 연도는 **양력 변환 후 출생 날짜**로 판단합니다. 예를 들어 음력 2030년 말이 양력 2031년이면 지원 범위 밖이며, 양력 1950년 초에 해당하는 음력 1949년 날짜는 지원합니다.

## 설치 없이 언제든 사용하기

`npm run build:offline`로 생성되는 `downloads/saju-program.html`은 CSS, 계산 엔진, 한국 음력 자료까지 포함한 **단일 HTML 파일**입니다. 이 파일을 컴퓨터에 저장하고 Chrome/Edge에서 더블클릭하면 인터넷·서버·Node.js 없이 사용할 수 있습니다. 생년월일은 외부에 전송되지 않습니다. 모바일에서 파일 실행이 제한되는 경우에는 배포된 웹 주소를 사용하세요.

생성 후 `SAJU_CHROMIUM_PATH=/usr/bin/chromium npm run test:offline`으로 실제 인터넷 차단 상태에서 PC/모바일 폭의 계산과 JSON 다운로드를 검증할 수 있습니다. 클라우드의 관리형 Chromium은 file:// 직접 열기를 차단하므로 테스트에서는 생성 파일의 원문을 빈 페이지에 주입해 검증합니다. 개인 PC의 파일 직접 열기와는 구분됩니다.

## GitHub Pages 영구 웹 주소

`.github/workflows/pages.yml`은 main 변경마다 계산 테스트와 빌드를 거쳐 GitHub Pages에 자동 배포합니다. 저장소의 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택해야 합니다. 계정·저장소 요금제에 따라 Pages 사용 가능 여부가 다를 수 있습니다. Actions의 `만세력 웹사이트 배포`가 성공하면 Pages 설정 화면의 Visit site에서 실제 주소를 확인하세요. main에 수정사항을 올리면 같은 주소가 자동 갱신됩니다.

이 저장소의 기본 Pages 주소는 `https://logan880712.github.io/saju-program/`입니다. **배포 성공 전에는 활성 주소로 간주하면 안 됩니다.** Pages URL은 온보딩 클라우드 프로세스와 독립적이며 컴퓨터나 모바일 브라우저에서 사용할 수 있습니다. 원국 입력은 브라우저에서 계산하므로 API 키나 서버가 필요 없습니다.
